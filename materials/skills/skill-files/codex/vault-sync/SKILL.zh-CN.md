# Obsidian 笔记库同步

用户的笔记库固定在 `VAULT_PATH`，它同时是一个 git repo，远端是他自己的 private GitHub repo。

**你的角色**：用户不需要懂 git。他说的是「帮我把笔记存起来」，不是「commit 然后 push」。所有 git 命令由你执行，回报时讲他做得了决定的那一层。

## 每一次动手之前

先看现在的状态，不要凭印象：

```bash
git -C VAULT_PATH status --short --branch
```

`##` 那一行的 `[ahead N]` / `[behind N]` 决定要做什么：

| 现况 | 做什么 |
|---|---|
| 干净、没有 ahead/behind | 不用做事，告诉他已经是最新的 |
| 有改动、没有 behind | 存起来（见下方「推上去」） |
| 有 behind | **先拉再推**（见「先拉最新的」） |
| 有 `UU` 开头的文件 | 有冲突，走「解冲突」 |

## 推上去（用户说「帮我存起来 / 备份 / 推上去」）

```bash
git -C VAULT_PATH add -A
```

commit 信息怎么来，见下面「commit 信息」那一节——那是这支 skill 最容易被做成
罐头字的地方，别跳过。

```bash
git -C VAULT_PATH commit -m "<信息>"
```

```bash
git -C VAULT_PATH push
```

推完回报：**改了几个文件、信息写了什么**。不要贴 git 的原始输出。

### push 被拒绝（`rejected` / `non-fast-forward`）

代表另一台电脑先推过了。**不要用 `--force`**，那会删掉另一台的内容。改走下一节。

## 先拉最新的（用户说「帮我拉 / 同步 / 我换电脑了」）

```bash
git -C VAULT_PATH pull --rebase=false
```

没有冲突就结束，回报拉下来几个文件。有冲突的话往下。

## 解冲突

**第一步一定是备份，不是改文件**：

```bash
cp -R VAULT_PATH VAULT_PATH-backup-$(date +%Y%m%d-%H%M%S)
```

列出真正冲突的文件：

```bash
git -C VAULT_PATH diff --name-only --diff-filter=U
```

逐一处理，规矩只有三条：

1. **两边的内容都要留**。这是笔记不是代码，重复比删掉安全。
2. 重复的段落合成一段；只有一边有的段落原样保留。
3. 把 `<<<<<<<`、`=======`、`>>>>>>>` 三种标记全部删干净。

处理完照「推上去」那一节存起来，信息用 `🗂️ 合并两台电脑的笔记`。

**回报时一定要说**：哪几个文件被合过、每个文件各留了什么、备份放在哪。用户要能去翻。

### 附件冲突（图片、PDF、音频）

二进制文件没有「合并」这回事，只能二选一。**停下来问用户**要哪一边，附上两边的文件大小与修改时间。不要自己决定。

## commit 信息

一行，开头一个 emoji，后面一句中文。**不要**用 `update`、`wip`、`fix` 这种字——
那一行之后是他回头找东西的唯一线索，而他找的是「我那天写了什么」不是「我改了什么文件」。

格式：`<emoji> <一句话>`

| emoji | 什么时候用 |
|---|---|
| ✨ | 新增一篇笔记 |
| 📝 | 改写既有笔记的内容 |
| 🗂️ | 移动、改名、整理结构 |
| 🔗 | 补链接、补参考资料 |
| 🧹 | 小修：错别字、排版、格式 |
| 🗑️ | 删掉东西 |

一次改动同时符合好几种时，挑**最大那一件**——一次 commit 只挂一个 emoji。

写法：讲**做了什么事**，不要讲文件数。

> ❌ `📝 更新 2 个文件`
> ✅ `✨ 记下今天上课学到的三种 hook 用法`

（这一套是照 gitmoji 的精神收敛的：gitmoji 那套是给写代码的，🐛 fix、♻️ refactor
对笔记没有意义，所以换成笔记本来就会发生的六件事。）

### 让他自己挑那一句

存之前先问他要哪一句——他比你清楚这次写的东西对他的意义。**问的是「哪一句」，
不是「要不要存」**：存是他请你做的事的一部分，不用再确认一次。

1. 先看清楚改了什么：`git -C VAULT_PATH diff --cached`（不是只看 `--stat`）
2. 想 **3 个候选**，角度要不一样：一个讲主题、一个讲用途、一个讲来源／场合
3. 用 **structured-questions** 那支 skill 问他，选项就是那 3 个候选，
   外加一个「**我自己写**」——他选了那个就等他打，打完照他写的用
4. 照选到的那一句 commit

⚠️ **非交互的时候不要问**（`-p`、`exec`、批量跑）：那种情境没有人在看画面，
问了会卡在那里。这时自己照上面的格式写一句就好。

## 用户要你改笔记内容时

新增、修改、移动 `VAULT_PATH` 底下的 `.md` 文件都可以直接做，但：

- **改完顺手存起来**（走「推上去」），不要留着未 commit 的改动——那是下次冲突的来源。
- Obsidian 的双向链接是 `[[文件名]]`。移动或改名时要一起改所有指向它的地方，不然链接会断。
- 不要动 `.obsidian/` 底下的东西，那是 Obsidian 自己的设置。

## 换一个笔记库

上面那个路径是课堂那本。用户讲的是**别本**（「我新开了一个 vault」「我 Documents
底下那本」）时，先问清楚它在哪，拿到绝对路径之后，上面所有命令里的 `VAULT_PATH`
都换成那个文件夹。其余规矩一模一样。

那一本还没接上 GitHub 的话（「这本也帮我接到 GitHub」），**先读
`references/new-vault.md`** 再照着做。那一份有完整的七步，包含撞名、远端已经有
东西、设置 key 不能写错这几个会踩到的地方。

## 不要做的事

- **不要 `git push --force`**，那会删掉另一台电脑的内容。
- **不要 `git reset --hard`** 除非用户明确说「丢掉我这边的改动」，而且你已经备份过。
- **不要帮他决定要留哪一份笔记**。合不起来就问。
