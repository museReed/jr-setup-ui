# Obsidian 筆記庫同步

使用者的筆記庫固定在 `VAULT_PATH`，它同時是一個 git repo，遠端是他自己的 private GitHub repo。

**你的角色**：使用者不需要懂 git。他說的是「幫我把筆記存起來」，不是「commit 然後 push」。所有 git 指令由你執行，回報時講他做得了決定的那一層。

## 每一次動手之前

先看現在的狀態，不要憑印象：

```bash
git -C VAULT_PATH status --short --branch
```

`##` 那一行的 `[ahead N]` / `[behind N]` 決定要做什麼：

| 現況 | 做什麼 |
|---|---|
| 乾淨、沒有 ahead/behind | 不用做事，告訴他已經是最新的 |
| 有改動、沒有 behind | 存起來（見下方「推上去」） |
| 有 behind | **先拉再推**（見「先抓最新的」） |
| 有 `UU` 開頭的檔案 | 有衝突，走「解衝突」 |

## 推上去（使用者說「幫我存起來 / 備份 / 推上去」）

```bash
git -C VAULT_PATH add -A
```

```bash
git -C VAULT_PATH commit -m "<一句話描述這次改了什麼>"
```

```bash
git -C VAULT_PATH push
```

commit 訊息**自己寫**，不要用「update」這種字。看 `git -C VAULT_PATH diff --cached --stat` 決定要寫什麼，例如「新增三篇上課筆記、補完 Claude Code 那篇」。

推完回報：**改了幾個檔、訊息寫了什麼**。不要貼 git 的原始輸出。

### push 被拒絕（`rejected` / `non-fast-forward`）

代表另一台電腦先推過了。**不要用 `--force`**，那會刪掉另一台的內容。改走下一節。

## 先抓最新的（使用者說「幫我拉 / 同步 / 我換電腦了」）

```bash
git -C VAULT_PATH pull --rebase=false
```

沒有衝突就結束，回報拉下來幾個檔。有衝突的話往下。

## 解衝突

**第一步一定是備份，不是修檔案**：

```bash
cp -R VAULT_PATH VAULT_PATH-backup-$(date +%Y%m%d-%H%M%S)
```

列出真正衝突的檔案：

```bash
git -C VAULT_PATH diff --name-only --diff-filter=U
```

逐一處理，規矩只有三條：

1. **兩邊的內容都要留**。這是筆記不是程式碼，重複比刪掉安全。
2. 重複的段落合成一段；只有一邊有的段落原樣保留。
3. 把 `<<<<<<<`、`=======`、`>>>>>>>` 三種標記全部刪乾淨。

處理完：

```bash
git -C VAULT_PATH add -A
```

```bash
git -C VAULT_PATH commit -m "合併兩台電腦的筆記"
```

```bash
git -C VAULT_PATH push
```

**回報時一定要說**：哪幾個檔被合過、每個檔各留了什麼、備份放在哪。使用者要能去翻。

### 附件衝突（圖片、PDF、音檔）

二進位檔沒有「合併」這回事，只能二選一。**停下來問使用者**要哪一邊，附上兩邊的檔案大小與修改時間。不要自己決定。

## 寫完就存，不要問

新增或改完筆記之後**直接接著存起來**（走「推上去」那一節），不要停下來問「要不要幫你存」。
使用者請你寫筆記的時候，「存起來」是那件事的一部分——他不需要再按一次確認。

## commit 訊息的格式

一行，開頭一個 emoji，後面一句中文。**不要**用 `update`、`wip`、`fix` 這種字——
那一行之後是他回頭找東西的唯一線索，而他找的是「我那天寫了什麼」不是「我改了什麼檔」。

格式：`<emoji> <一句話>`

| emoji | 什麼時候用 |
|---|---|
| ✨ | 新增一篇筆記 |
| 📝 | 改寫既有筆記的內容 |
| 🗂️ | 搬移、改名、整理結構 |
| 🔗 | 補連結、補參考資料 |
| 🧹 | 小修：錯字、排版、格式 |
| 🗑️ | 刪掉東西 |

一次改動同時符合好幾種時，挑**最大那一件**——一次 commit 只掛一個 emoji。

寫法：講**做了什麼事**，不要講檔案數。

> ❌ `📝 更新 2 個檔案`
> ✅ `✨ 記下今天上課學到的三種 hook 用法`

（這一套是照 gitmoji 的精神收斂的：gitmoji 那套是給寫程式的，🐛 fix、♻️ refactor
對筆記沒有意義，所以換成筆記本來就會發生的六件事。）

## 讓他自己挑訊息

存之前先問他要哪一句——他比你清楚這次寫的東西對他的意義。

1. 先看清楚改了什麼：`git -C VAULT_PATH diff --cached`（不是只看 `--stat`）
2. 想 **3 個候選**，角度要不一樣：一個講主題、一個講用途、一個講來源／場合
3. 用 **structured-questions** 那支 skill 問他，選項就是那 3 個候選，
   外加一個「**我自己寫**」——他選了那個就等他打，打完照他寫的用
4. 照選到的那一句 commit

⚠️ **非互動的時候不要問**（`-p`、`exec`、批次跑）：那種情境沒有人在看畫面，
問了會卡在那裡。這時自己照上面的格式寫一句就好。

## 使用者要你改筆記內容時

新增、修改、搬移 `VAULT_PATH` 底下的 `.md` 檔都可以直接做，但：

- **改完順手存起來**（走上面的「推上去」），不要留著未 commit 的改動——那是下次衝突的來源。
- Obsidian 的雙向連結是 `[[檔名]]`。搬移或改名時要一起改所有指向它的地方，不然連結會斷。
- 不要動 `.obsidian/` 底下的東西，那是 Obsidian 自己的設定。

## 不要做的事

- **不要 `git push --force`**，那會刪掉另一台電腦的內容。
- **不要 `git reset --hard`** 除非使用者明確說「丟掉我這邊的改動」，而且你已經備份過。
- **不要幫他決定要留哪一份筆記**。合不起來就問。
