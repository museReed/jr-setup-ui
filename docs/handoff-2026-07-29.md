## 四層驗證，各自證明不同的事

| 驗證 | 叫 AI | 證明什麼 |
|---|---|---|
| 每列狀態 / 「驗證安裝」 | 否 | 檔案內容逐字相同、註冊正確、**實際餵指令給 hook 看它擋不擋**、命名寫得進 sync 檔 |
| 「驗證 hook 會擋」 | 是 | Claude Code 真的載入並執行 block-chained-bash |
| 「驗證自動命名」 | 是 | Claude Code 真的觸發 session-auto-namer |
| 「驗證回覆格式」 | 是 | output style / config.toml 真的改變了回覆（五取三） |

判準一律是「**真的生效了嗎**」而不是「指令有沒有跑完」。

## 這輪踩到的坑（都只在 Windows 或壓縮檔情境現形）

| 坑 | 症狀 | 修法 |
|---|---|---|
| `new URL().pathname` | `C:\C:\...` 找不到模組 | `fileURLToPath`，加「不准用 `.pathname`」的測試 |
| `.gitignore` 的 `AGENTS.md` 沒錨定 | 本機有、壓縮檔沒有 | 改 `/AGENTS.md`，加「素材必須被 git 追蹤」的測試 |
| 整篇回答塞進指令參數 | cmd.exe 吃掉換行與 `\|` | prompt 全部走 stdin |
| 猜 `wt.exe` 路徑 | 裝了卻報「尚未安裝」 | 問 `Get-Command wt` |
| 白名單路徑斜線方向 | 規則永遠對不上 | win32 轉反斜線，加迴歸測試 |
| 診斷程式碼自己炸 | `stdout.resume()` 早把輸出丟了 | 留著 stdout；**加診斷也要跑失敗路徑** |

**貫穿全部的教訓**：這些沒有一個能在 macOS 開發機上測出來。凡是「只有某平台會錯」
的判斷，都要補一條**在任何平台都會紅**的測試（形狀檢查、源頭檢查），不然下次
還是只會在 VM 上炸。

## 工作方式

- 實作交給 codex：`{SKILL_DIR}/run-codex-task.sh <repo 絕對路徑> <spec 絕對路徑>`
  - spec 放 `.codex-task/spec.md`，舊的移到 `.codex-task/done/`
  - **寫完 spec 自檢：驗收條件提到的每個檔案都要在「允許改動」清單裡**
    （這一輪又踩了一次——codex 正確地停下來回報矛盾）
- **不要相信 codex 自報的測試結果**，一律自己重跑
- 所有實跑一律用假的 HOME（`HOME=/tmp/... node scripts/...`），不要碰真正的
  `~/.claude`、`~/.zshrc`
- Windows 行為一律實測，不要推論
