# 上過課的同學要重跑嚮導

> 給講師與助教。學生只需要看「給學生的四句話」那一節。

## 結論：不要叫他們移除任何東西

嚮導是設計成可以重複跑的。叫學生先移除 Claude、Codex、git、Python 是**淨損失**：

- Claude、Codex、gh 的登入都要重跑一次 device flow（課堂上最花時間的一段）
- 他自己寫在 `CLAUDE.md` / `config.toml` 裡的規則會不見
- 移除本身也會失敗、也會卡住，多一批要處理的狀況

一鍵指令跟新生用同一條，不需要特別的版本。

## 重跑時每一類東西會發生什麼

| 類別 | 已經裝過的話 | 學生要做什麼 |
|---|---|---|
| CLI（claude / codex / git / gh / node / python） | 檢查回 `ok`，安裝鍵整顆收掉 | 什麼都不用做 |
| 他自己改過的規則檔（`CLAUDE.md`、`~/.codex/config.toml`、`AGENTS.md`） | 不覆蓋，顯示「已有你自己的版本，需要合併」 | 按**「開終端用 AI 合併」**。合併完之前驗證鍵是鎖著的 |
| 我們發的素材（skill、hook、output-style） | 逐字比對，舊版顯示「檔案在，但內容跟這一版不同」 | 按**安裝**就更新 |
| claude-hud 狀態列 | 舊的一行寫法會被判成要重裝 | 按**安裝** |
| Obsidian 筆記庫 | 永遠留一顆按鈕（`reinstallable`） | **先完全關掉 Obsidian 再按** |

`~/.claude/settings.json` 在被改寫前會自動備份成 `settings.json.bak.<時間戳>`。

### 合併會開一個真的終端視窗

按下去會跳出一個新的終端，AI 在**那裡面**動手，不是在嚮導的背景裡。學生要看那個視窗、
回答它的問題（要不要修改檔案 → 是）。

⚠️ **Windows 上第一次可能會多跳一個要系統權限的框，那是正常的，要按「是」。**
那是 Codex 的沙箱在設定資料夾權限。

為什麼不在背景跑（Windows 真機撞出來的三件事）：

1. **看不到授權框。** 那個框跳在嚮導視窗後面，學生順手關掉——嚮導只拿到
   `ShellExecuteExW failed: 1223`（使用者取消），畫面上是一張沒頭沒尾的紅卡
2. **答不了問題。** AI 中途要批准寫入時，背景那條沒有人可以回答，它只能自己放棄
3. **燒錢燒得沒人看見。** 實測一次失敗的合併跑了 7 分鐘、53 萬 tokens，全部在重試同一件
   做不到的事

嚮導這邊不是等視窗關掉，是**輪詢那個檔案**——工作坊那段真的進去了才算完成，判準跟畫面上
那一列用的是同一個函式。所以學生可以開著視窗去做別的事，也可以先關視窗再回來。

背景那條（`merge-config-step`）程式裡留著沒刪：哪天要做無人值守的批次安裝會用到它。

## 舊東西會不會殘留？三類行為不一樣

| 東西 | 重跑會不會清掉舊的 |
|---|---|
| hook 註冊（`settings.json`） | ✅ 會。`mergeAgentHookRegistrations` 先把「指令含我們 marker」的整批刪掉再重寫 |
| tab-sync 的 rc 區塊 | ✅ 會。用 marker 整塊替換 |
| Codex 的 `config.toml` 舊 key | ✅ 會。`RETIRED_CODEX_KEYS` 主動註解掉 |
| `CLAUDE.md` / output-style / hook 腳本檔 | 覆蓋同名檔 |
| 白名單規則 | ⚠️ 只加不減。舊規則會累積，大多無害 |
| **skill** | ❌ **不會清。** 裝到固定路徑再覆蓋，改名或停發的 skill 會留下，而且 Claude 照樣載入它 |

所以嚮導會掃出來，但**不自動刪**。

### ⚠️ skill 有三條規則，不要混在一起看

| 規則 | 看的是什麼 | 實務上抓得到嗎 |
|---|---|---|
| **殘留**（`straySkillDirs`） | 已經**停發**的名字還躺在機器上 | ❌ 幾乎抓不到。`RETIRED_SKILLS` 是空的，從來沒有 skill 被停發過 |
| **要覆蓋的落點**（`scanWizardSkills`） | 嚮導**這一輪要寫的資料夾**已經有東西了 | ✅ 回訪學生幾乎必中——上一輪裝的就是同樣那幾支 |
| **位置退場**（`legacyCodexSkillDirs`） | 我們發過的名字躺在 codex **搬家前**的 `~/.codex/skills` | ✅ 上一輪用過 codex 的機器會中，而且它是唯一會講話的一條 |

前兩條是「名字退場」與「這個資料夾我要寫」，第三條是「整個根目錄已經不會被讀到」。
下面三節分開講。學生看到的也是三條不同的提示。

### 規則一：停發的 skill 殘留

⚠️ **能被標出來的只有 `src/legacy.js` 的 `RETIRED_SKILLS` 這份名單裡的名字**——工作坊
自己發過、現在停發的那些。學生自己裝的 skill 永遠不進入判斷。

第一版不是這樣：當時的規則是「不在這一輪發的名單裡就算殘留」。那條在真的機器上跑出來
是**七個全是他自己的 skill、工作坊殘留零個**——而那個零是結構性的：
`git log --diff-filter=D materials/skills/**` 掃過全部歷史，沒有任何 skill 目錄被刪過或
改名過。與其讓學生看一堆跟他無關的東西然後學會忽略它，不如把範圍鎖死。

**所以這份名單今天是空的，畫面上什麼都不會出現——那是正確的。**
哪天真的把某支 skill 改名或停發，把舊名字加進 `RETIRED_SKILLS`，它才會開始作用。

講在兩個地方：

- **第一頁與技能包那一段的段落狀態列**（進度條上方那條琥珀色的）：「這台機器上還有 N 個
  不是這一輪發的 skill：⋯」。第一頁是為了讓回訪的學生在動手裝任何東西之前就看到；
  技能包那一段是他真的在想「我有哪些 skill」的時刻。中間那幾段不放，免得同一句話跟著
  他一路走
- **終端與「看原始輸出」**：完整路徑在這裡

不只印在終端的理由：終端是「現在正在做什麼」，開頁那一刻學生在看第一張卡，等他走到技能
包那一段，那幾行早就被後面的輸出推掉了。

### 清理：一個一個搬，不是刪

那一句旁邊每一個殘留各自一顆「搬走 ⟨名字⟩」。按下去會把那個資料夾搬到

```
~/.jr-setup/removed/<時間戳>/<名字>/
```

**沒有「全部搬走」，而且這是刻意的。** 名單本身已經只認我們自己發過的名字，誤傷的風險
小了很多——但搬走是不可逆感很強的動作，而學生可能對其中某一支還有感情（例如他改過它）。

搬而不刪的兩個理由，第二個比第一個重要：

1. 誤判的時候搬得回來（把資料夾搬回原位就恢復）
2. **出事的時候查得到當時搬走了什麼**。直接刪掉的話，「嚮導把我的東西弄壞了」這種
   回報就沒有任何可以對照的東西

兩層把關：伺服器只讓合法形狀的名字通過（擋掉斜線、`..`、空白），腳本再自己重跑一次
偵測、確認那個名字真的在殘留清單裡才動手。這一輪正在發的 skill 永遠不在那份清單裡。

## 規則二：嚮導要裝的 skill 已經在那裡了

這條才是回訪學生真正會遇到的。上一輪裝的就是 `handoff`、`auto-rename`、
`structured-questions`、`vault-sync`，這一輪嚮導要寫的是**同樣那幾個資料夾**。

**為什麼直接覆蓋不夠**：安裝只寫我們現在發的那幾個檔案。舊版留下的其他東西——以前有、
現在沒有的附屬檔——會留在同一個資料夾裡，而**Claude 載入 skill 時看的是整個資料夾**。
檢查也看不到它們，因為檢查只逐字比對我們發的那幾個。

所以第一頁會出現一條琥珀色提示：

> 這台機器上已經有 N 支嚮導要裝的 skill：⋯
> 〔先搬到隔離區，再裝乾淨的〕

按下去 = 舊資料夾搬到 `~/.jr-setup/removed/<時間戳>/<agent>/<名字>/`，然後裝一份乾淨的。

### 三個刻意的決定

**掛在第一頁，不是技能包那一段。** 時機才是重點：走到技能包那一段時，安裝已經一路覆蓋
過去了，那顆按鈕只剩事後補救。第一頁是他還沒動手裝任何東西的那一刻。
⚠️ 技能包那一段原本那一顆（「把工作坊的 skill 換新」）**同時拿掉了**——同一件事兩個入口，
行為遲早會走鐘。

**偵測 + 按鈕，不自動搬。** 學生可能改過其中某一支，未經同意動他的檔案是另一種傷害。
代價是他可能不按就往下裝——那就回到覆蓋安裝，跟以前一樣，不會更糟。

**範圍含第三方 skill**（`npx skills add` 裝的 `frontend-design`、`skill-creator`、
`playwright`）。它們跟工作坊自己那幾支一樣是覆蓋不刪。
⚠️ 代價：重裝要**連得上網**。斷網時那幾支會失敗而工作坊那幾支不會，所以腳本分開報結果，
不要讓一支第三方的失敗看起來像整批都壞了。舊的仍在隔離區，搬得回來。

⚠️ **範圍是「嚮導自己要寫的資料夾」，不是「不在這一輪名單裡的東西」。** 學生自己裝的
skill 一支都不會出現在這份清單裡——那正是規則一第一版被推翻的教訓，不要再走回去。

## 規則三：codex 的 skill 搬過家，舊路徑那幾支還在原地

Codex 換過 skill 的位置：**舊版讀 `~/.codex/skills`，現在的官方 user 目錄是
`~/.agents/skills`**。搬家是「換一個地方讀」，不是「把舊的搬過去」——上一輪裝在舊路徑的
那幾支原地留著，而 codex 已經不會載入它們。

**為什麼要單獨一條，而不是併進規則二**：規則二看的是「我等一下要寫的資料夾已經有東西」。
一台上一輪只用過舊路徑的機器，新落點（`~/.agents/skills`）是空的——規則二會誠實地回報
0，第一頁整個安靜，看起來像「這台是乾淨的」。而學生看得到 `~/.codex/skills` 裡有
`handoff`，怎麼用都沒反應，那種落差他自己查不出來。

> Codex 的舊路徑底下還躺著 N 支上一輪的 skill：⋯
> 〔搬走 ⟨名字⟩〕

⚠️ **這一條不接「換新」那顆，只接「搬走」。** 新落點那份是嚮導這一輪自己會裝的；舊路徑
這幾支沒有對應的重裝動作——它們就是要離開，不是要換一份。

⚠️ **範圍只有「我們自己發過的名字」**（`legacyCodexSkillDirs`）。學生自己放在
`~/.codex/skills` 的東西不進入判斷，理由同規則一第一版被推翻的教訓。

搬走走的是同一支腳本（`scripts/quarantine-skills.mjs`），用 `--scope=legacy-codex` 區分
——同一個名字可能同時躺在兩個地方，而那是兩個不同的資料夾。兩層把關不變：伺服器擋形狀、
腳本自己重跑一次偵測。

⚠️ `--scope=legacy-codex` 那條**一律用兩個 agent 的步驟算名單**，不跟著學生勾了哪些工具走
——偵測那邊就是寫死兩個。跟著選擇走的話，只勾 claude 的學生看得到按鈕、按下去卻是「不在
清單裡」。

三條規則的掃描結果**都會寫進「看原始輸出」，包含一支都沒找到**（掃了哪個路徑、比對了幾個
名字、結果幾支）。這個檢查存在的原因就是「安靜的機器」，所以它自己更不能是安靜的：沒有
那幾行的話，「查過、乾淨」跟「根本沒查」在畫面上一模一樣。

## npm 裝的舊版：嚮導現在會講，但不會擋

**如果他當初的 claude / codex 是用 `npm install -g` 裝的**，落點跟嚮導現在用的原生安裝器
（`~/.local/bin`）不同，兩份可以並存。`claude --version` 回的是 PATH 裡先出現的那一份
——嚮導只看 exit code 的話會判成 `ok`、不去裝新的，他用的卻是舊的那份。

嚮導的判準是**問 `npm ls -g --depth=0 --json`**，不是看路徑長得像不像 npm 裝的。

⚠️ **原本的判準是「PATH 上有幾份」，那個寫法漏掉最重要的一種機器**：只有 npm 那一份、
沒有新版。那一列是綠的、只有一份，看起來毫無問題，但他用的就是上一輪的舊版，而且嚮導
看它跑得起來就不會去裝新的。（Reed 這台的 `codex` 正是這樣——改判準之前完全不會被指出來。）

所以兩種機器的文案不一樣：

| 機器狀態 | 第一頁那條說什麼 |
|---|---|
| 只有 npm 那一份 | 「你現在用的就是上一輪的舊版——嚮導看它跑得起來，不會另外幫你裝新的」 |
| 新舊並存 | 「跑起來的是 PATH 裡排在最前面那一份，不一定是新的」 |

PATH 上找到的每一份路徑照樣寫進「看原始輸出」，`npm ls` 的答案排在份數前面——那才是判準，
份數只是佐證。

⚠️ **只回報、不改紅燈。** 跑得起來就是跑得起來，把一台能用的機器判成失敗只會擋住他；
而「哪一份才是他要的」我們也不知道（他可能刻意留著舊版）。跟舊 skill 殘留同一套處理。

環境段那一句旁邊有一顆「移除 npm 裝的舊版」。它只碰兩個寫死的套件名
（`@anthropic-ai/claude-code`、`@openai/codex`，就是舊一輪 `npm install -g` 裝的那兩個），
而且先問 `npm ls -g` 確認真的有才動手——用路徑猜的話，原生安裝器裝的那份也可能被誤判。

⚠️ **畫面與移除腳本共用同一句 `npm ls -g`，這是刻意的。** 兩邊判準不一樣的話會出現
「畫面說有、按下去卻說沒有」——最傷信任的那種不一致。`test/backend-layers.mjs` 有一條
釘住它。

代價是環境檢查多一支 spawn，npm 冷啟動要 1–3 秒。它跟其他檢查併行跑，不會把第一頁
整個拖住。

可逆：真的需要舊版，`npm install -g` 裝得回來。

要自己確認路徑的話：

```bash
which -a claude codex
```

```powershell
Get-Command claude, codex -All | Select-Object Source
```

⚠️ 「npm 版與原生版並存會出問題」這件事**沒有實測過**，是從落點差異推出來的。目前的
處理方式（講出來、不擋）正是為了這個不確定性。

### mac 上這個情境本來就很少見

macOS 的 `npm install -g` 會寫 `/usr/local/lib/node_modules`，而官方 .pkg 裝的 Node 把那個
目錄留給 root——學生帳號直接 EACCES（這正是 `installers.js` 開頭寫的、當初放棄 npm 改用
原生安裝器的理由）。所以 mac 上的舊生多半**沒有** npm 版的 claude／codex 可以並存。

例外是他的 node 來自 nvm 或 Homebrew（全域目錄可寫），或是他當初用了 `sudo`。

⚠️ 那個例外不罕見：Reed 自己的 mac（node 來自 nvm）**兩支都是 npm 裝的**，
`claude` 還跟 `~/.local/bin` 的新版並存。用 nvm 的人在開發者裡是多數。

⚠️ 用 `sudo` 裝的那種，嚮導那顆「移除 npm 裝的舊版」會失敗——我們刻意不帶 sudo。
它會把 npm 自己的 EACCES 印出來並回非零，**明確地失敗，不是靜靜地什麼都沒做**。那時
請學生自己跑 `sudo npm uninstall -g <套件名>`。

## 給學生的四句話

1. 跑一鍵指令，跟第一次上課時一樣
2. **第一頁如果出現琥珀色的提示，先按那幾顆再往下走**（把舊 skill 搬到隔離區、移除 npm
   裝的舊版）。都是可逆的，舊的東西搬到 `~/.jr-setup/removed/` 底下，沒有被刪掉
3. 從第一張卡照順序走，已經是綠色的就跳過
4. 看到「需要合併」一定要按「開終端用 AI 合併」，不要跳過
5. 走到 Obsidian 那張之前，先把 Obsidian **完全關掉**
