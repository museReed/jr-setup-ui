# 文案審閱準則

審「學生看得到的每一句話」用的八條。Reed 在 2026-08-06 逐張過「讓 AI 能跑起來」那五張卡時定下來的，之後每張卡、每次改文案都照這個掃。

**先講判準的來源**：這八條不是從「怎麼寫好文案」推導出來的，是從「有人真的卡住過」長出來的。所以看到一條覺得囉唆時，先去找它是為了接住哪個坑——多半找得到。

---

## 1. 不預設學生懂技術

學生群體不是資工背景。出現一個他不認得的詞，那句話對他就等於空的。

| 別寫 | 寫 |
|---|---|
| 「另一個**會寫程式**的助手」 | 「另一個 AI 助手」 |
| 「不用開網頁就能推上 GitHub、**開 PR**」 | 不要出現 PR 這種詞 |
| 「系統預設擋掉所有 **.ps1 腳本**」 | 「後面每一張卡按下去都會失敗」 |

## 2. 描述要講「為什麼要裝」，不是列特性

特性對學生沒有意義，他無從判斷那算好還是不好。

> ❌ `ghostty.detail`「**分頁、複製貼上都正常**，後面每一步都在這個視窗裡做」
> ——「分頁、複製貼上都正常」跟「為什麼要換掉你現在的終端機」沒有關係。學生會想：我現在這個也正常啊。

## 3. 會開視窗的動作，要說視窗在哪、沒出現怎麼找

**這是全站規則，不是單張卡的問題。** 每一個會開終端或瀏覽器的地方都適用。

Windows 從 XP 起就有「防搶焦點」：只有剛收到使用者輸入的程式才能把視窗拉到最前面，其他一律只閃工作列。嚮導的呼叫鏈（瀏覽器點擊 → node → `cmd /c start` → `wt.exe`）不具備那個資格，所以**新終端多半不會跳到最前面**。mac 走 `open` 比較好，但也不保證。

程式擋不住這件事（詳見 handoff 的討論），所以文案要接住：

- 說清楚「會開一個新的終端視窗」
- 說「沒有自己跳出來的話去哪找」——**而且要用該平台的講法**：mac 講 Dock 或 Mission Control，Windows 講工作列，不要混用
- 登入那幾格同理：會開瀏覽器、要貼一串 code，卡片要先講

## 4. 驗證完要叫學生關掉那個終端

每跑一次驗證就開一個新視窗，一路做下來會累積十幾個。沒人告訴他可以關，他就不敢關。

## 5. 描述要帶這張卡的流程，不只結果

學生按下按鈕之前要知道「接下來會依序發生什麼」。只寫結果的話，中間任何一步跟他預期不同，他都會以為壞了。

## 6. 學生會卡住的地方

寫文案時把「他照做但沒發生」那條路走一遍。

> `claude` 那張的「跳出方框時按 1. Yes, try it」——**已經選過的人不會再跳**。重跑的學生卡在「我沒看到方框」而不敢勾。

## 7. 講了實作、沒講現象

**順序永遠是現象在前、原因在後。**

> 「跳出方框時按 1. Yes, try it」只講了要按什麼，沒講那個方框在問他什麼（切換顯示模式）。學生不知道自己在同意什麼。

## 8. 沒講要等多久 / 一句話講了兩件事

- **等多久**：brew 裝 Ghostty 要拉幾百 MB、行為驗證每次跑兩趟 LLM 要一分多鐘、playwright 第一次要下載一顆瀏覽器。畫面沒動時學生會以為當掉，然後按取消。
- **一句兩件事**：`git.detail` 一句 63 字塞了 Git、GitHub CLI、登入三件事，而那張卡正好是三列。

---

## 操作步驟不要擠在卡片上

第 3、5、6、7 條會讓卡片文案不斷變長。解法不是寫短，是**搬家**——卡片留「做完會多出什麼」，操作細節搬進彈窗。

**只給學生真的要動手的那些做**，不是每一格：

| 類型 | 數量 | 要不要彈窗 |
|---|---|---|
| 眼睛項（只有他看得到的） | 11 | ✅ |
| 人工項（全螢幕那三格） | 3 | ✅ |
| 系統驗（程式查得到的） | 其餘 | ❌ 他不用動 |

這條跟既有的規則是同一條：**程式驗得到的就不問學生，程式管不到的才要教他怎麼做。**

**彈窗裡用時間軸呈現**（design system 的 `.ds-timeline--draw`：捲到才畫線、圓點依序亮起）。要求：

1. **把「要點哪顆按鈕」也編進時間軸**，跟「會看到什麼」交錯排——學生照著一格一格做，不用自己在文字裡找動作
2. **依那張卡實際有的元件寫**：那張卡沒有的按鈕不要出現在步驟裡
3. **不要用錄影或 GIF**——檔案大、改一個字要重錄，而且要出雙平台雙語四份。用 `.ds-timeline--draw`、`.ds-step-seq`、`.ds-term--typing` 這種程式演出來的，改文案就是改一行字串，i18n 自動跟上

現成零件都在 design system 裡：`.ds-modal-overlay` / `.ds-modal-panel`（彈窗）、`.ds-timeline--draw`（依序畫線）、`.ds-step-block` / `.ds-step-seq`（分步）、`.ds-term--typing`（終端打字）、`.ds-browser`（瀏覽器示意）。`.ds-checklist` 嚮導現在就在用。
