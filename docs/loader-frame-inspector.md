# loader-claude 幀檢視器 — PRD

一頁決策紀錄。工具本體：`tools/loader-frame-inspector.html`（可直接用瀏覽器開，離線可用）。
線上版（私有 artifact）：<https://claude.ai/code/artifact/cc34650c-983d-4845-91f7-05d6af0c1cde>

## 為什麼有這個東西

終端裡那支 loader 動畫要改成三個狀態（待機／打電腦／收起電腦），而 Lottie 是靠**幀號**切段的。
`loader-claude.json` 沒有 marker、沒有圖片資產（4 個純向量圖層全程 0–43），
所以沒有任何 id 可以指——「哪幾幀屬於哪一段」只能靠人眼看。

在這之前唯一的辦法是把整支動畫播出來用肉眼抓時間點，那既不精確也講不清楚：
「大概轉到一半」沒辦法變成 `playSegments([9, 35])`。

## 這個工具要解決的一件事

**讓人把「我看到的動作分界」變成可以直接寫進程式的幀號區間。**

## 決策

1. **一個檔案、離線可用**：lottie 播放器與動畫資料都內嵌。開檔就能用，不需要跑伺服器、不需要網路。
   代價是檔案 280KB，而且動畫資料被複製了一份——換動畫時要重新產生（見「怎麼重新產生」）。
2. **逐幀而非播放**：主預覽預設停住，用拖桿／方向鍵一幀一幀走。播放只是輔助（先看一輪找大概位置）。
   邊播邊抓分界抓不準，那正是這個工具要取代的做法。
3. **整卷 44 幀同時攤開**：下方一次畫出所有幀。分界是「相鄰兩幀的差異」，兩幀要能並排比較才看得出來。
4. **圈選的結果是一行純文字**：`待機 0–8 / 打電腦 9–35 / 收起 36–42`。
   直接貼回對話就是交付物，不需要另外描述。
5. **被圈到的幀在整卷上有底色**：圈完要能一眼驗證範圍對不對，而不是回頭重數一次。

## Non-Goals

- 不編輯動畫。只讀不寫，不產生新的 Lottie。
- 不寫回 `loader-claude.json`（不塞 marker）。段落定義留在程式碼那側，動畫檔維持原樣。
- 不做通用的 Lottie 檢視器。它只認這一支動畫、只切這三段。
- 不進 `public/`，也不掛在嚮導的伺服器上。學生不會用到它。

## 否決了什麼

**在 Lottie 裡加 marker，讓程式讀 marker 名稱。**
否決理由：那要改動畫檔本身，而動畫是外部素材，之後換一版就要重做一次；
段落定義寫在程式碼裡（一個常數）改起來更直接，也看得到 diff。
重開條件：如果之後動畫改成由設計端維護、而且他們願意在 After Effects 裡標 marker，這個決定要重看。

**逐幀輸出成一張 PNG 聯絡表。**
第一版就是這樣做的，Reed 的回應是「但我要能怎麼看」——靜態圖上每格太小，
分不出相鄰兩幀的差異，也沒辦法放大確認。互動式拖桿解決的正是這件事。

## 這一輪的產出

| 段 | 幀 |
|---|---|
| 待機 | 0–8 |
| 打電腦 | 9–35 |
| 收起 | 36–42 |

（Reed 用這個工具圈出來的。之後接到 `playSegments` 時以這組為準。）

## 怎麼重新產生

動畫換版之後，把 `public/vendor/lottie-light.min.js` 與 `public/vendor/loader-claude.json`
內嵌進模板即可——工具本身沒有其他相依。目前是手動產生的一次性工具，
還沒值得為它寫建置腳本；哪天換動畫換到第三次，再把這段變成腳本。
